# Онбординг — план правок

Порядок всего репо, включая Салаку: [fixes.md](fixes.md). Здесь только детали пунктов 1–6; карточка хода стыкуется с снимком черновика из общего плана.

По живой Аллерии (`domain_b06a7d3a7abc`) и застрявшему второму игроку. Анкету как разговор не убираем. Не бэкфиллим Аллерию. Три старых красных теста (`plot-canon`, `suspense-engine`) не трогаем.

**Порядок внутри онбординга:** 1 → 2+5 (одна правка карточки хода) → 3 → 4 → 6.

## 1. Старт говорит только система

Агент никогда не пишет, что остров создаётся. Сейчас он может это сказать, а система ещё и подменяет ответ на «Поднимаю остров…». Если Claude/ключи мертвы, игрок слышит старт, потом тишину или сбитый стейт.

На проде ломался вызов из-за незаданных переменных окружения. В этом случае система должна написать ошибку и явно сказать, что остров **не создан**.

### Делать

- Промпт онбординга: запрет на «поднимаю / создание началось / правитель напишет сам». После `start_new_game` реплика агента может быть пустой.
- Если генезис реально стартовал — игроку уходит только прогресс-бар (`pushProgress(0, 'начинаю…')` уже есть). `formatOnboardingStartReply` убрать или не слать: это дубль бара голосом агента.
- Если `start_new_game` не стартовал (отказ инструмента) — любые фразы про создание срезать. `usedStart` только при успешном вызове (`ok !== false` / `startFlag.started`). Сейчас `usedTools.has('start_new_game')` ловит и отказ и глушит автостарт плюс срез ложного старта.
- Если генезис упал (нет ключей, Claude, таймаут) — уже есть `Не удалось создать остров: …`. Дописать: остров не создан, можно снова попросить старт. Сбросить `phase: generating`.
- Детектор ложного старта оставить страховкой (в т.ч. «создание X началось»). Это второй слой, не основной UX.
- «Запускай» / «запускаем» в лексикон `playerConsentsToStart` — мелочь на случай, если агент забыл tool. Не главный фикс.

### Файлы

- `src/game/onboarding.js` — `formatOnboardingStartReply`, `claimsOnboardingGenerating`, `planOnboardingAutoStart`, `playerConsentsToStart`
- `src/game/app.js` — `usedStart`, подмена ответа, `genesis.failed`
- `config/default.yaml` — `agents.onboarding`
- `tests/onboarding-start.test.js`

## 2. Карточка хода = JSON осей, без «активного вопроса»

Анкета как UX ок. Ломает схема «одна открытая ось»: агент выдумывает `economy` / `era`, `set_axis` падает, ошибка течёт игроку (`Нет оси «economy»`).

Каждый ход в системный промпт класть **полный бланк**, не список закрытых и не указатель «следующая ось»:

```json
{
  "landscapeForm": { "name": "Форма ландшафта", "value": null },
  "climateBand": { "name": "Климат", "value": "WARM" },
  "productiveBase": { "name": "Опора хозяйства", "value": null }
}
```

Ключи — только каталог (`GENESIS_AXIS_ORDER`). `null` = пусто. Значение — id каталога или свободная строка игрока (кастомная формулировка нормальна).

### Делать

- Писать любой ключ через `set_axis(axisId, value)` по ходу разговора, не по указателю `nextAxis` / `openAxisTarget`.
- `resolve_axis` как «закрой текущую» убрать из brief и questions (или оставить тонкой обёрткой над `set_axis`). Карточка больше не говорит «следующая ось, один вопрос за ход».
- В questions агент может спрашивать по одной пустой оси — это речь, не скрытый указатель в туле.
- `unknown_axis` игроку не показывать (`appendOnboardingToolErrors`). Короткий алиас-слой (`economy` → `productiveBase`, `era` → `historicalCondition`) — только сетка; основной фикс это JSON с настоящими id.

### Файлы

- `src/game/onboarding.js` — `formatOnboardingStatusCard`
- `src/game/genesisAxes.js` — формат бланка, алиасы
- `src/game/onboardingTools.js` — `set_axis` / `resolve_axis`
- `config/default.yaml` — `РЕЖИМ brief` / `questions`
- `tests/onboarding-start.test.js`

## 3. Имя города — `%cityName`, не нормализация текстов

`set_city_name` меняет `concept.name`, но не `preview`. Генезис склеивает opening lore из концепта и дописывает предложения старого preview — отсюда «Таверн стоит…» при городе Аллерия. Не переписывать все поля при переименовании.

### Делать

- `submit_concept`: поле `name` отдельно; в `preview` / `identity` и прочей прозе только `%cityName`. В именительном: «город %cityName стоит…». Косвенные падежи обходить («здесь», «этот город»), чтобы онбординговый превью не кривился.
- Показ игроку: `%cityName` → текущее `concept.name` (именительный). Переименование меняет только `name`, шаблон не трогаем.
- Longform-генезис: везде `%cityName` поставить реальное имя в нужном падеже, плейсхолдер не оставлять.
- `openingLoreFromConcept` не режет сырой preview со старым именем: либо подстановка, либо лор из структурированных полей + `%cityName`.

`set_city_name` снова пишет только `concept.name` — этого достаточно.

### Файлы

- `src/game/genesisConcept.js` — промпт, `openingLoreFromConcept`, показ preview
- `src/game/genesis.js` — longform, инструкция про падеж
- `src/game/onboarding.js` — карточка: подстановка при показе
- `config/default.yaml` — `genesisConcept` и агенты генезиса

## 4. Имя бога: запятая разрешена

Отдельный антиспам «не принимать анкетные фразы» не делаем. Кастомная строка оси живёт в JSON осей (п.2), не в `set_patron_name`. Если бланк осей виден, ответ про хозяйство не должен уезжать в покровителя.

### Делать

- В `validatePatronName` разрешить запятую. `Ксарр, Шепот Листьев` — валидное имя.
- По желанию разрешить кавычки/`«»`, если их и так нормализуем. Длина 40 символов остаётся.

### Файлы

- `src/game/onboarding.js` — `validatePatronName`
- тесты рядом с валидацией имён

## 5. Directives — тот же бланк, заполнение в этом ходе

Не извлекать `required` из брифа задним числом перед концептом. Агент каждый ход видит пустые массивы и пишет, как только игрок зафиксировал факт.

В ту же карточку, что оси:

```json
{
  "required": [],
  "preferred": [],
  "forbidden": []
}
```

Правило: конкретный факт города в **этом** сообщении («джунгли», «набеги чудовищ», «плато никто не знает») → `required` до ответа игроку. Окрас/вкус → `preferred`. «Не хочу X» → `forbidden`.

### Чтобы не забывал второй tool

- У `set_axis` флаг `required` / `preferred`. Свободная формулировка игрока с `required: true` сразу попадает в директивы. Каталожный id (`WARM`) в required не копируем.
- У `set_player_brief` те же массивы в одном вызове: бриф + директивы за ход.
- Если бриф уже длинный, а `required` пуст — карточка: «жёсткие факты ещё не в required, выпиши их сейчас, не зови концепт». Чеклист агенту, не парсер текста.

`request_city_concept` в quick не блокируем из-за пустого required.

### Файлы

- `src/game/onboarding.js` — карточка (вместе с п.2)
- `src/game/onboardingTools.js` — `set_axis`, `set_player_brief`, `set_player_directives`
- `config/default.yaml` — онбординг: заполняй директивы в том же ходе
- тесты онбординга

## 6. `generating` не залипает

`phase: generating` пишется в драфт на ходе, который стартовал генезис. После успеха онбординг не чистится. После фейла живой флаг снимается, в Mongo может остаться generating.

### Делать

- Таймаут `generatingUsers`: снять флаг, написать что остров **не** создан.
- В `genesis.failed` сбросить фазу драфта (см. п.1).
- После успешного домена — стереть онбординг-драфт, не оставлять `phase: generating` на биндинге.

### Файлы

- `src/game/app.js` — `startDomainGeneration`, `generatingUsers`, сохранение драфта
- `src/game/onboarding.js` — `deriveOnboardingPhase`
