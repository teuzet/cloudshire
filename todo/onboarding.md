# Онбординг — питч-объект

Онбординг больше не собирает оси, директивы и READY-концепт. Он собирает один объект, показывает его игроку и по явному согласию отдаёт в генезис.

Из чата ничего не экстрактим: ни имя бога из «Ага», ни одно слово с заглавной, ни дописку реплик в бриф.

---

## Питч — единственное состояние

```js
{
  cityName: null,       // строка
  description: null,    // 1200–1800 знаков, 2–3 абзаца
  patronName: null,
  patronGender: null,   // male | female
}
```

Каждый ход агент видит этот JSON в system-карточке плюс что пусто и что можно делать. Не показываем оси, required, фазы `intro/collecting/pitched`. История чата — контекст; память города — только эти четыре поля.

---

## Тулы

Один патч и два специальных.

- `update_pitch` — любое подмножество полей. Код валидирует имя города (длина, занятость), имя бога (не подтверждение вроде «ага/да/ок»), пол. Космологию на `description` проверять эвристикой; конфликт вернуть агенту, в объект не писать.
- `generate_random_city` — только путь «случайный город». Бросает оси, зовёт писателя питчей, записывает `cityName` + `description`. Патрона не трогает.
- `start_new_game` — только если все четыре поля заполнены **и** в этом ходе игрок явно согласился (`да / подходит / начинаем / создавай`). Иначе отказ тула: «сначала покажи питч и дождись согласия».

Подтверждение названия и правки — тоже `update_pitch`.

---

## Разговор

**Старт.** Знаешь ли, чем хочешь играть? Если да — напиши, что для тебя важно.

Край: первое сообщение уже длинное описание → не спрашивать «знаешь ли», сразу путь A.

### Путь A — есть пожелания

Текст живёт в чате. Агент 2–4 наводящими вопросами (не анкета) закрывает дыры конкретного текста: что запомнится чужаку; чем живут, если убрать главную метафору; где город кончается; кто решает за всех. Затем сам собирает питч через `update_pitch`. Имя и пол бога спрашивает прямо, когда описание уже есть.

### Путь B — не знает → случайный город

`generate_random_city`: код бросает оси → агент-писатель питчей пишет `description` 1200–1800 и черновик `cityName` → это сразу в объект. Онбординг спрашивает только патрона и правки, если имя не нравится.

Оси читает только писатель. Игроку не показываем, в питч-объект не кладём. После броска их можно выкинуть: в генезис уходит проза.

### Путь C — не знает → анкета

Список не совпадает с осями. Ответы не кладём в структуру: агент спрашивает по одному, вслух, своими словами. После последнего сам пишет питч.

---

## Оси случайной генерации

Задают логику места, не декорацию. Яркость даёт сочетание + `oddity`, где писатель обязан выдумать конкретную вещь.

**1. `islandBody` — тело острова**  
Не «вулкан / лес / нагорье», а метафора для географии, районов, путей.

- хребет — всё держится на одной гряде
- чаша — низина внутри, край выше
- ступени — живут ярусами
- обломки — куски и трудные переходы
- плита — открыто, негде спрятаться
- нутро — есть слой под или внутри, не только «на поверхности»
- кайма — жизнь на ободе, середина другая

**2. `weather` — погода как характер**  
Сырой сумрак, жёсткий свет, ветер с края, пепел и долгие сумерки, резкая смена сезонов, стоячий холод, густой воздух.

**3. `livelihood` — чем жив город**  
Логика труда, не отрасль. Дальше хозяйство, ремёсла, повседневность.

- циклы — растят, пасут, бродят, ждут сезона
- тело острова — берут камень, глину, руду, торф
- передел — делают из местного сырья
- счёт и запас — хранят, меряют, распределяют
- путь за добычей — ходят за тем, что само не стоит на месте
- двор тянет несколько дел, одной отрасли нет

**4. `bond` — чем скреплены «свои»**  
Род / соседство / артель / очередь-клятва / культ покровителя / несколько опор сразу.  
Отсюда общество, власть, часть обычаев.

**5. `hold` — сколько острова своё**  
Не «монстры снаружи».

- почти всё в деле
- ядро своё, дальше реже
- пятна освоения
- город — исключение в неотмеченном
- своё и несвоё перемешаны в самой застройке

**6. `era` — момент истории**  
Давно без слома / после разрыва / распухает / редеет / старый порядок спорит с новым.

**7. `temper` — публичный нрав**  
Суровый, праздничный, сварливый, скрытный, тщательный, неугомонный.

**8. `oddity` — правило этого места**  
Закрытый тип, открытая вещь. Писатель обязан назвать конкретное и подчинить ему быт.

- живое правило — закон следует за циклом живого
- вещественное — из этого строят или этого нельзя
- место — одно место раздаёт права
- срок — календарная обязанность
- умение — ремесло = гражданство
- память — что должны помнить или не называть
- след сопряжения — остаток давней стыковки (вещь, закон, люди); чужой остров как государство не выдумывать

Дубли `landscapeForm` + `settlementPattern` и каталог «пашня / стада / цех» не берём.

## Вопросы анкеты

Не форма генезиса и не структура в памяти. Каждый вопрос кормит пачку аспектов longform. Шесть вопросов, по одному за ход, ответ свободный. Тон клерка.

**1. Место** → общий облик, география, климат  
«Какой это остров как место жизни: тесно, высоко, сыро, каменисто, темно, ветрено? Что в этом дар, что мука?»

**2. Дело** → хозяйство, ремёсла, повседневность  
«Чем люди заняты от сезона к сезону? Какое умение в доме стыдно не иметь?»

**3. Свои** → общество, власть  
«Кто здесь “мы”? Как на деле принимают решение, которое касается всех?»

**4. Повтор** → обычаи, вера  
«Что делают каждый год обязательно — праздник, счёт, тишина, служба покровителю, общая починка?»

**5. Тело города** → районы, места, пути  
«Если идти от самой старой постройки к последнему двору — что меняется под ногами? Где город кончается и начинается просто остров?»

**6. Память** → история, предания, хронические риски  
«Что из прошлого всё ещё правит: постройка, долг, закон, стыд, гордость? О какой части своего острова до сих пор нет одной общей истории?»

Не спрашивать: чужак на рассвете, «не трогай», дети, охота на тварей, устройство стены, чужие острова.

Путь A этими шестью не ходит.

---

## Показ и согласие

Когда четыре поля есть, агент пересказывает питч (имя, описание, как к нему будут обращаться) и спрашивает, всё ли так.  
Не устраивает → `update_pitch`, снова показать.  
Устраивает → `start_new_game`.

Код не стартует по «ага» сам: нет патрона из подтверждения, нет автоимени из заглавной буквы. Согласие имеет смысл только как разрешение тулу старта при уже полном объекте.

---

## Что уходит в генезис

В `generateDomain` — этот объект.

- `cityName` / `patronName` / `patronGender` — locked-поля как сейчас.
- `description` — канонический питч вместо `concept.preview` + `playerBrief` + `required`.
- Оси случайной генерации не тащить: они уже в тексте.
- `frozenConcept` на входе генезиса собирается адаптером: `{ status: 'READY', name, preview: description }`. Longform в этом заходе не меняем.

---

## Что выкинуть из онбординга

Режимы `quick/brief/questions`, оси на драфте, `axisInterview`, `playerDirectives` до генезиса, `request_city_concept` как шаг онбординга, `applyUserNamedPatron` / автоимя города из реплики, дописка коротких сообщений в бриф, карточка осей.

Оставить: проверку занятого имени, эвристику космологии на тексте питча, прогресс генезиса, longform.
