# Система фронтов: техническое устройство

Игровой замысел описан в доке «Система фронтов: от намерения игрока до наследия».
Здесь описано, как он лежит в коде: модель данных, числа, события и агенты на каждом этапе.
Прежняя версия этого файла описывала старый движок (drift, effort, каскад) и больше не действует.

Главное правило: **модель решает смысл, код решает количество**. Агент выбирает ярлык из закрытого
списка или пишет короткий текст. Все числа считает `src/core`, все значения лежат в `config/game.yaml`.

## 1. Сущности

### Объект (`WorldObject`)

Поля, которые добавила система, помимо имени, вида, описания, версий и ссылок:

| Поле | Смысл |
|---|---|
| `statEffect` | Вклад в статы в сырых единицах города. Пункты стата = сырое × `city.statScale`. |
| `refs` | Связи с другими объектами. По ним роли динамик ищут соседей и обновляются идущие дела. |
| `parentId` | Вложенность. Удаление родителя уносит детей. |
| `hidden` | Скрытый объект: его видят агенты, но не жрец и не игрок. |
| `occupiedBy` | Фронт, который занял объект. Занятый объект даёт три четверти вклада. |
| `temporary` | Живёт, пока жив фронт, к которому привязан. |
| `attach` | `{ frontId, rate }`: помощник (rate > 0) или помеха (rate < 0), единиц в игровой месяц. |
| `themes` | Одна или две темы города. |
| `freshDay` | День создания или последней перемены. Год после него объект получает вес ×3 при подборе ролей. |

**Выбывший объект.** Случившаяся беда не стирает объект, а выводит его из строя (`out`): он остаётся
в городе, ничего не даёт и помнит прежний вклад. Так бывает с любым родом из `fronts.objects.keepLost`:
здание сгорело, артель распущена, люди ушли. Выбывает объект, когда беда его «удаляет» или отнимает
переоценкой весь положительный вклад; удар побочной беды ограничен малым минусом. Дело игрока
с итогом `restore_object` (ставка `restore`) возвращает прежний вклад. Что утрачено безвозвратно,
решает Развязчик по смыслу (`lost_forever`): такое уходит из города и остаётся только в памяти жреца.

**Память объекта** (`log`). Запись хроники о событии ложится короткой строкой в лог каждого объекта,
с которым что-то случилось (последние `logMax`). Жрец видит список выбывшего и последние строки
памяти; хроника при этом остаётся про события.

### Фронт (`Front`)

| Поле | Смысл |
|---|---|
| `form` | `deed` дело, `tension` напряжение, `threat` угроза, `clock` часы, `find` поиск. |
| `origin` | `player` проект игрока, `deed` атомарное дело, `complication`, `echo`, `story`. |
| `capacity`, `progress`, `progressDay`, `ratePerDay` | Шкала работы. Прогресс ленивый: считается по целым игровым дням. |
| `milestones`, `milestonesFired` | Вехи делят шкалу поровну, последняя веха это завершение. |
| `deadlineDay` | Срок: у угроз, часов, напряжений (день прорыва) и возможностей. |
| `pulseDay` | День следующего месячного броска: у дел «невозможно» и недостижимых; у посаженной истории это день её следующего события. |
| `stake` | Операции при завершении. |
| `failStake` | Операции по сроку. |
| `risk`, `tempo` | Ступень лестницы и темп проекта (−1, 0, +1). |
| `key` | Запечатанное: `moves` (3–5 ходов) и `twist` (подвох исхода, если исход не известен заранее). |
| `footprint` | Отпечаток: `{ objectId, relation, reason }`, отношения `occupies`, `linked`, `pressures`, `benefits`. |
| `parentId` | Фронт-родитель: у атомарных дел и осложнений. |
| `bound` | `slow`, `rollback` или `cancel`: чем привязанное осложнение грозит родителю. Пока жива привязанная угроза откатом или отменой, родитель стоит. |
| `atStake` | Сколько стоит на кону в единицах работы: из этого считается ёмкость угрозы и напряжения. |
| `plus` | Плюсовой фронт (возможность): срок истёк, значит просто исчез. |
| `unattainable` | Причина, по которой цель недостижима. Такое дело идёт до краха. |
| `rollsFired` | Сколько бросков риска сработало: каждый третий отдаётся плюсовой записи. |
| `projectId` | Проект, этапом которого является фронт. |
| `script` | Материал посаженной истории: события и улики. |
| `siteId` | Промежуточный объект («Стройка башни»): временный, исчезает с концом дела, при отмене остаётся стоять без вклада. |
| `profile` | Стат, к которому дело относится сильнее всего: для поправки сановника. |
| `deed` | У атомарного дела: вид (`push`, `helper`, `clear`), вердикт Судьи и цель. |
| `outburst`, `dynamicId` | Слова Костюмера о том, что случится без вмешательства, и запись словаря, из которой фронт собран. |

Ставка собирается из закрытого списка операций (`StakeOp`): `create`, `revalue`, `modify`
(переписать и переоценить по намерению; поток заранее разворачивает её в `revalue`), `delete`, `reveal`,
`fact`, `link`, `progress`, `rollback`, `cancel`, `attach` (помощник или помеха на фронте), `stats`.
Вклады в операциях заданы в пунктах стата, в сырые единицы объектов их переводит ядро.

### Поручение (`Assignment`)

Сановник ведёт один фронт. Поля: `frontId`, `office`, `text` (стратегия словами игрока),
`verdict` (`spot_on`, `fits`, `off`), `tempo` (темп поручения). У сановника есть `temper`:
`hasty`, `even` или `slow`, код бросает его при рождении города.

### Проект (`Project`)

Цепочка этапов от Разбивщика. Запускается только первый этап, следующий ждёт слова игрока.
Ждущие проекты жрец видит в блоке хода. Город также хранит веру (`faith`), память словаря динамик
(`dynamicsUsed`: когда запись срабатывала в последний раз) и предупреждение о недостижимой цели.

## 2. Числа

Все значения условные и лежат в `config/game.yaml`, раздел `fronts`.

| Величина | Правило |
|---|---|
| Выработка сановника | 4 единицы за игровой месяц (2 в реальный час). |
| Класс вклада | нет 0, малый 2, средний 5, большой 12, огромный 30, со знаком. |
| Базовая цена | правка и факт 1; норма, практика, вещь, ресурс, достопримечательность 2; группа, персона, умение 3; учреждение, место, квартал, здание 4; большое сооружение и поселение 8. |
| Ёмкость дела | сумма модулей вклада + базовая цена. Перемена объекта: сумма модулей разницы + половина цены. |
| Масштаб и вехи | до 6 одна веха, 7–15 две, 16–35 три, от 36 четыре. |
| Соответствие | в точку ×1,25; годится ×1; мимо ×0,5. |
| Поправка сановника | 0,8 + 0,2 × стат/100, плюс 0,15, если дело его профиля. |
| Темп | три рычага складываются: проект, поручение, характер. Множитель скорости и шанса беды 1 + 0,2 × сумма. |
| Помощник и помеха | +2 и −2 единицы в месяц. Помеху убирает дело на 15% ёмкости фронта, не меньше 2. |
| Угроза по статам | ёмкость равна удару в пунктах (`threat.capacityShare` 1), не меньше 2. Месяц сановника спасает 4 пункта, стройка приносит около 2,5. |
| Угроза делу | привязанная к делу: 40% работы, что на кону (`threat.boundShare`). |
| Срок беды | не короче заданного и не короче ёмкость / 4 × 1,5 месяца: один сановник успевает, если взялся в первую треть. |
| Напряжение | гасится за половину удара по статам или за 20% работы дела, не меньше 1; прорыв через 2–4 месяца. |
| Возможность | ёмкость 50% выигрыша. |
| Сроки | беда от своего риска 1 месяц, от мира и эха 4 месяца. |
| Разовый вклад | атомарное дело на 15% ёмкости родителя, не меньше 2; столько же, умноженное на соответствие, получает родитель. |
| Занятый объект | даёт 75% вклада, пока идёт дело. |
| Авария | теряется 25% набранного прогресса. |
| Исход, не известный заранее | жребий: 60% как задумано, 40% с подвохом. |

Лестница риска: шанс осложнения на вехе 0 / 15 / 35 / 60 / 100%. Тяжесть: «обычно» всегда лёгкое,
«сложно» поровну, выше всегда тяжёлое. Привязанная беда грозит помехой («обычно»), откатом на веху
(«сложно») или отменой («рискованно», «невозможно»). «Безопасно» при спешке бросает как «обычно». «Невозможно» не снижается
и бросает ещё раз в месяц между вехами. Каждый третий сработавший бросок отдаётся плюсовой записи.

## 3. События фронта

Один вид задания в очереди города: `front_event`. Код ставит его на ближайшее из трёх: следующая веха,
срок, месячный бросок. Обработчик досчитывает прогресс и разбирает одно событие.

| Событие | Что делает код | Какие агенты |
|---|---|---|
| Веха дела | бросок риска; у посаженной истории открывается улика | Агент битов; при выпавшем кубике сборка осложнения |
| Завершение дела | ставка, освобождение занятых, связи, бросок, свежесть | Агент битов, Оценщик вклада (подвох), Оценщик веры, Тематик, Судья (сосед), обновление, Летописец |
| Угроза снята | родитель снова идёт | Развязчик, Оценщик веры, Летописец |
| Срок угрозы | ставка провала: откат, отмена или переоценка | Развязчик, Оценщик веры, Летописец |
| Срок напряжения | прорыв: мелкое привязанное становится помехой, остальное угрозой с коротким сроком | Летописец; у помехи ещё Развязчик |
| Срок часов | ставка | Переписчик, Развязчик, Летописец |
| Срок возможности | исчезает, тихая запись в хронику | нет |
| Месячный бросок | осложнение без вехи; у посаженной истории наступает её следующее событие | сборка осложнения или Агент битов |
| Завершение атомарного дела | ставка двигает родителя, бросок риска идёт против родителя | Агент битов; при выпавшем кубике сборка осложнения |

## 4. Агенты по этапам

Все агенты работают на модели по умолчанию (`config/agents.yaml`, gpt-luna). У каждого папка
`src/agents/<имя>/`: `prompt.md`, `schema.ts`, `run.ts`, `README.md`.

Правила промптов:

- агент ничего не знает об игре, промпт описывает только его задачу;
- в промпте только то, что нужно по контракту;
- у генеративных агентов нет примеров, у оценщиков есть размеченные примеры;
- вместо запретов положительные критерии.

### Воля игрока

Жрец остаётся прежним. Его инструменты `assign_officer` и `order_change` ведут в один поток
`playerWill`, `withdraw_assignment` снимает сановника с дела.

| Шаг | Агент | Папка | Вход | Выход |
|---|---|---|---|---|
| 1 | Толкователь | `will-interpreter` | приказ, сановник, идущие дела, ждущие проекты | ярлык `project`, `strategy`, `deed`, `tempo`, `cancel`, `continue`; дело; вид атомарного дела; цель; способ; два темпа |
| 2 | Страж канона | `canon-warden` | цель, устройство мира, факты города, объекты | `possible`, `amended` или `unattainable`; причина; поправленная цель; нехватки |
| 3 | Разбивщик | `stage-planner` | цель, нехватки, объекты | от 1 до 4 этапов: работа, результат (новый объект, перемена, снос, факт), место работ, известен ли исход |
| 4 | Оценщик вклада | `contribution-appraiser` | результат, сводка города | до четырёх эффектов: стат, направление, размер |
| 5 | Картограф отпечатка | `footprint-mapper` | работа, результат, объекты | до шести отношений с причиной |
| 6 | Оценщик риска | `risk-appraiser` | работа, отпечаток | ступень и причина |
| 7 | Сборка | код | | ёмкость, вехи, занятые объекты, место работ, бросок исхода |
| 8 | Запечатыватель | `key-sealer` | дело, участники, подсказка | 3–5 ходов; подвох, если исход брошен «с подвохом» |
| 9 | Судья соответствия | `alignment-judge` | способ, дело, ходы | `spot_on`, `fits`, `off` |
| 10 | Жрец | `priest` | итог инструмента | условия словами: сколько работы, насколько рискованно, кто занят |

Ветки Толкователя:

- `project`: шаги 2–10. Сановник из инструмента сразу становится ведущим.
- `strategy`: только Судья соответствия. Вердикт хранится в поручении.
- `deed`: атомарное дело, малый дочерний фронт с одной вехой. Виды: `push` (разовый прогресс родителю: ёмкость дела × соответствие), `helper` (временный помощник: Разбивщик называет объект, Оценщик вклада его цену), `clear` (убрать помеху). Судья соответствия и Оценщик риска вызываются всегда.
- `tempo`: меняет темп проекта или поручения, агентов нет.
- `cancel`: отмена дела. Место работ остаётся без вклада, занятые свободны, помощники исчезают.
- `continue`: следующий этап ждущего проекта, шаги 4–10.

**Недостижимая цель.** Страж отвечает `unattainable` с причиной. Первый раз жрец получает
предупреждение и передаёт его игроку. Повторный приказ в течение 60 игровых дней (Примерщик
подтверждает, что замысел тот же) запускает дело одним этапом и не меньше чем в две вехи: ёмкость считается так, будто
цель возможна, кубик не бросается, на каждой вехе и раз в месяц приходит тяжёлая побочная беда или
находка, привязанных угроз нет. На последней вехе результата нет: Развязчик пишет крах и оставляет
след попытки.

### Веха и осложнение

| Шаг | Агент | Папка | Вход | Выход |
|---|---|---|---|---|
| 1 | Агент битов | `beat-writer` | дело, доля пути, способ, разрешённые эффекты | событие в 2–3 фразы и эффект `none` или `reveal` |
| 2 | Бросок | код | ступень, сумма темпов | нет, лёгкое, тяжёлое или плюс |
| 3 | Отбор записей | код | словарь динамик, отпечаток, момент, тяжесть | пары «запись и объект» |
| 4 | Примерщик | `role-fitter` | одно условие, один кандидат | да или нет |
| 5 | Жребий | код | веса: свежесть ×3, давность записи | порядок, в котором спрашивают Примерщика (не больше шести вопросов); берётся первая подошедшая пара |
| 5а | Сочинитель динамики | `dynamics-composer` | дело, отпечаток | вид беды, цель, скелет, что помогает. Только если не подошла ни одна запись |
| 6 | Костюмер | `costumer` | скелет, объект в роли, дело, темы, имена | название, описание, слух, прорыв, новый объект |
| 7 | Оценщик вклада | `contribution-appraiser` | объект и что с ним случится | новый вклад. Только у побочных и плюсовых |
| 8 | Запечатыватель | `key-sealer` | новое дело, подсказка записи | ходы |
| 9 | Сборка | код | | ёмкость, срок, заморозка родителя |

Лёгкое осложнение рождается напряжением, тяжёлое угрозой, помехой или аварией. Авария это мгновенный
удар: четверть набранного прогресса теряется и появляется помеха. Та же запись с тем же участником
не открывается второй раз, пока первая беда жива. Если Оценщик вклада не увидел разницы, на кону
остаётся малый урон главному стату объекта.

### Конец угрозы и завершение

| Когда | Агент | Папка | Вход | Выход |
|---|---|---|---|---|
| Угроза снята или сработала, крах недостижимого | Развязчик | `resolver` | беда, участники, способ, исход, разрешённые эффекты | 2–3 фразы и эффект: `none`, `fact`, `link`, `keep`, `trace` |
| Событие с волей бога | Оценщик веры | `faith-appraiser` | текст события | случай (`harm_willed`, `harm_unguarded`, `harm_averted`, `boon_willed`, `none`) и сила |
| Завершение этапа | Тематик | `theme-tagger` | объект, темы города | одна или две темы |
| Завершение этапа | Судья соответствия | `alignment-judge` | результат, соседнее дело, его ходы | «в точку»: результат становится постоянным помощником соседа |

### Последствия, обновление, хроника

**Последствия рождает фронт, а не перемена.** Изменение объекта само новых фронтов не рождает, и
вклад соседей по связям не пересчитывается (эхо убрано 2026-11-12 после плейтеста: оно превращало
шум оценки в обязанности игрока). Фронт рождает фронты в свои моменты жизни через словарь динамик:
на вехе, при завершении и при срыве (беда случилась; бросок `fronts.failure`, роли из того, по чему
ударила беда, и его соседей). Что родится при срыве и при посеве, решает режиссёр (раздел 5а).

**Обновление после перемен.** Код находит идущие дела, которых касается изменённый объект. Для
каждого Примерщик отвечает, существенна ли перемена. Если да: Запечатыватель пишет ключ заново, Судья
переоценивает стратегию ведущего, Оценщик риска ступень, Переписчик (`description-rewriter`)
описание. Обновление не порождает новых обновлений.

**Хроника.** Код собирает перемены события в список («дифф»): что появилось, изменилось, исчезло,
какие дела начались и кончились. Летописец (`chronicler`) пишет по сути события и этому списку запись
в 2–4 фразы. Вестник (`herald`, прежний) делает из записи весть игроку. Веха без перемен попадает в
хронику словами Агента битов.

## 5. Словарь динамик

Записи лежат в `config/game.yaml`, `fronts.dynamics`; две из них выключены до своих
механик («Взгляд извне», скрытое свойство результата). Поля записи:

| Поле | Смысл |
|---|---|
| `id`, `enabled` | Имя записи и включена ли она. |
| `class` | `bound` бьёт по делу, `side` по объекту, `plus` удобный случай. |
| `when` | `milestone`, `completion` или `failure`. |
| `light`, `heavy` | Во что выливается лёгкое и тяжёлое осложнение: `tension`, `threat`, `hindrance`, `accident`, `clock`, `opportunity` или `null`. |
| `from` | Откуда берётся объект в роль: отношения отпечатка, `helper`, `site`, `result`, `nearby`, `same-type`, `struck` (то, по чему ударила беда). |
| `types` | Какие виды объектов годятся; пусто значит любые. |
| `hits` | По чему бьёт: `parent`, `role` или `result`. |
| `condition` | Вопрос Примерщику; пустой значит подходит всегда. |
| `skeleton`, `helps` | Скелет для Костюмера и подсказка Запечатывателю. |
| `needsNew`, `newHidden` | Костюмер обязан описать нового участника; он скрыт от игрока. |
| `requires`, `minStep` | `noLead` (дело без ведущего) и ступень риска, с которой запись доступна. |
| `engine`, `source`, `sphere` | Оси режиссёра: двигатель истории, источник причины, сфера города (её сановник). |

## 5а. Режиссёр

Режиссёр (`src/core/world/director.ts`, числа в `fronts.director`) следит, чтобы игрока не заваливало
одинаковыми историями (Ник, 2026-11-12: старый движок тяготел к починке водосборов и бюрократическим
разбирательствам). Моделей в нём нет.

**Оси.** Жёсткая одна: тайна, то есть заранее посаженный скрытый ключевой объект или скрытый факт
(у записи словаря `needsNew` и `newHidden`; у заготовки скрытый объект, улики, ставка `uncover` или
`reveal`). Мягкие оси: двигатель (`refusal`, `feud`, `discovery`, `betrayal`, `dilemma`, `crisis`,
`success`, `ideology`, `opportunity`), источник причины (`people`, `custom`, `creature`, `ecology`,
`matter`, `sky`, `phenomenon`) и сфера города, а через неё сановник. Знака (беда или возможность) и
саспенса среди осей нет.

**Журнал.** Каждое рождённое осложнение и каждая посаженная история пишут свои оси в
`city.storyLog`. Окно памяти `windowDays`, свежее весит больше.

**Выбор.** Вес кандидата (пары «запись и объект» или заготовки) делится на `1 + repeatPenalty × повторы`
по каждой мягкой оси и на `1 + loadPenalty × дела сановника сферы`. Тайна желаннее в `mysteryBoost`
раз, пока её доля ниже `mysteryShare`, и во столько же раз реже, когда выше. Свободным генераторам
(Сочинитель динамики, посевщик без заготовки) режиссёр заказывает давно не бывшие двигатель,
источник и сферу словами из `engines`, `sources` и `spheres` (словами жизни города, не названиями показателей).
Источник причины умножает вес на `sourceTaste`: небо, существа, явления и наследие прошлого желаннее людских дел.

**Рождать ли.** Беды без ответа: угрозы и напряжения мира без ведущего. Чем их больше, тем реже срыв
тянет за собой новое (шанс `failure.chance`, умноженный на оставшееся место) и тем выше доля
удобных случаев среди выпавшего (от `plusBase` до `plusMax`, на вехах проектов тоже). При
`calmTroubles` бедах без ответа срыв даёт только удобный случай, а посев ждёт.

**Поток бед.** Цель баланса: при хорошей игре три сановника заняты бедами 70% времени, и город ничего
не теряет; рост даёт только оставшееся время. Режиссёр считает ёмкость бед мира, рождённых за
`pressure.windowMonths`, и сажает следующую историю, пока в месяц выходит меньше
`pressure.officers × pressure.share × work.unitsPerMonth` (8,4). Осложнения от дел игрока идут в тот же
счёт. `seeding.activeStories` остаётся потолком числа историй.

## 6. Вера

Вера хранится в городе. Она лениво тянется к среднему четырёх статов (десятая часть разрыва за месяц)
и получает импульсы по таблице `faith.impulses` от Оценщика веры. Мана по-прежнему приходит от веры.

## 7. Посаженные истории

Формат `scenarios/*.yaml` прежний. При посадке фронт истории ложится на новую модель: без дрейфа это
поиск (работа сановников доводит его до ставки), с дрейфом угроза со сроком (ставка сработает, если
не успеть). Ёмкость поиска и дела берётся из `seeding.capacity` по масштабу, ёмкость беды равна её удару по статам (таблица только когда удар не в числах), ходы ключа из `alignment` и улик.
Улики открываются на вехах работы, события истории наступают сами через равные доли срока.

**Масштаб истории.** Поле `scale` заготовки: `situation` (узкий случай), `episode` (общее событие,
порядки те же), `crisis` (глава в жизни города), `rupture` (перелом с «до» и «после»). Числа — в
`seeding.scale`. Масштаб задаёт три вещи.

- Бюджет статов. Числа ставок в файле становятся долями: удары бед истории вместе дают `budget`
  пунктов, выигрыши вместе тоже `budget`. От удара считаются ёмкость и срок беды; фронт с выигрышем
  стоит `gainShare` от выигрыша.
- Вклад при посадке. Объекты истории приходят без вклада, ценность они получают ставкой. Исключение: объект, который беда истории может отнять, приходит со своим вкладом, иначе беде нечего терять.
- Тяга. Всё, что история породила или изменила, получает метку `pull` (объекты посадки сразу,
  остальное при исполнении ставок). Тяга слабеет за `pullDays`, у перелома не слабеет. Режиссёр
  умножает на неё вес объекта в жребии осложнений (`director.pullWeight`) и называет Посевщику
  объекты с самой сильной тягой как то, вокруг чего город живёт сейчас.
- Частоту. У заготовок её задаёт их число по масштабам; история по зерну бросает жребий по `weight`
  не выше `freeMaxScale`.

**Беды и возможности.** Знак истории код берёт из её устройства: есть фронт, идущий к сроку сам,
значит беда, иначе возможность. Режиссёр ведёт два счёта: беду сажает по потоку работы (см. «Поток
бед»), возможность — пока за то же окно их посажено меньше, чем бед. Фронты истории-возможности
помечены `plus` и живут `seeding.chanceMonths`: не довели, история уходит.
Заготовка может задать заголовок и род фронта (`find`, `deed`, `threat`, `tension`), вклад и
скрытость объектов, ставку `uncover` (открыть скрытый объект) и `closes`: при завершении фронт
толкает другой фронт истории на долю его ёмкости и платит за это своей ёмкостью. Посевщик при
подгонке меняет слова, устройство берётся из заготовки.

**Есть ли такое.** Когда покровитель называет незнакомое, жрец зовёт тул `check_existence`.
Привратник канона (`existence-judge`) отвечает: уже есть; подробность без пользы (её дописывает
лормастер фактом); неизвестно (вещь с ценностью, её можно только найти проектом); нет в мире.
Неизвестное помечается в способе действий, чтобы рассказчики писали о поисках.

## 10. Отложено

- эффекты вехи «сдвинуть соседа» и «выбор»;
- находки, которые двигает любая активность рядом;
- целевая смесь двигателей у режиссёра (сейчас все равны), режиссёр для проектов игрока;
- сопряжение и запись «Взгляд извне»;
- наказ жрецу на ночь, заказ историй за ману;
- баланс всех чисел.
