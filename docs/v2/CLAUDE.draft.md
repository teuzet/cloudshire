# Cloudshire v2 — инструкции для Claude

> Черновик корневого CLAUDE.md. При старте ветки v2 переезжает в корень как `CLAUDE.md`.
> Подробности и обоснования: docs/v2/DEV_PRINCIPLES.md.

Текстовый мультиплеерный годсим в Telegram. Игрок говорит с верховным жрецом
летающего города. TypeScript strict, Node 20+, ESM. Общение с Ником по-русски.

## Карта

- `core/` — чистая логика мира. Без IO, без LLM, без `process.env`.
- `agents/<name>/` — LLM-агенты: prompt.md, schema.ts, run.ts, fixtures/, cassettes/, evals/.
- `flows/` — сценарии, которые склеивают core и агентов.
- `ports/` — интерфейсы LLM, Storage, Clock, Random, Notifier.
- `adapters/` — реализации портов (провайдеры, Mongo, in-memory, fake LLM).
- `clients/` — Telegram, mini-app, CLI. Тонкие, только сборка зависимостей и ввод-вывод.
- `checks/` — журнал проверок с настоящей моделью.

## Жёсткие правила

- Импорт только вниз: clients → flows → agents → core. Проверяет `npm run lint:deps`.
- Агенты не импортируют и не вызывают друг друга.
- SDK провайдеров, Mongo и Telegram импортируются только в `adapters/` и `clients/*/main.ts`.
- Время и рандом берутся из портов, не из `Date.now()` и `Math.random()`.
- Новый агент только через `npm run new:agent <name>`.
- Не запускай настоящие модели (`eval`, `--live`, `cassettes:record`), пока Ник явно не попросил.

## Команды

- `npm run check` — typecheck + lint + lint:deps + быстрые тесты. Гоняй перед каждым коммитом.
- `npm test` — unit, контрактные тесты и сценарии на fake LLM.
- `npm run scenario <name>` — прогон сценария flow без сети.
- `npm run eval <agent>` — eval на настоящей модели (только по запросу).

## Definition of done

1. `npm run check` зелёный.
2. Новая логика покрыта unit-тестами, изменённый агент — контрактным тестом.
3. Изменилось поведение агента или flow — есть фикстура или сценарий на это.
4. Обновлены README агента и CLAUDE.md слоя, если поменялись правила.
5. Один PR — одна фича. Правки чужого модуля объяснены в описании PR.

## Проверка по запросу Ника

1. Заведи папку `checks/YYYY-MM-DD-<slug>/` с `task.md`.
2. Допиши нужные фикстуры или сценарии, прогони eval/сценарий.
3. Запиши `results.json` (входы, ответы, оценки, модель, цена) и `report.md`
   (итог, проблемы с примерами, сравнение с прошлой проверкой этого модуля).
4. Добавь строку в `checks/INDEX.md`, закоммить.
5. Пришли Нику итог в 2–3 предложения и ссылку на report.md.
6. Если фикс очевиден, открой отдельный PR и повтори проверку на нём.
