# Стенд агентов

Здесь тюнят агентов по этапам игры без бота, Telegram и базы. Этап — это настоящий
игровой поток на памяти, ручных часах и сид-рандоме; меняется только модель.
Каждый прогон пишет общий отчёт и отчёт по каждому агенту, который в нём участвовал.

| Этап | Что делает | Агенты |
| --- | --- | --- |
| `genesis` | онбординг + генезис: разговор с проводником (или готовая «рыба») → город | onboarding-guide, city-genesis, world-objects-genesis, officer-nature, city-brief |
| `will` | реплики покровителя на снимке города → поручения, стройки, фронты со ставками и последствиями | priest, loremaster, assignment-evaluator, mutation-drafter, feasibility-judge, impact-judge, consequences-generator, consequence-judge |
| `seeding` | посев сюжетов из базы `scenarios/` или по зерну на снимок города | scenario-writer, front-chronicle, herald |

## Раскладка

```
bench/
  cases/<этап>/<кейс>.yaml   входы этапов
  states/<имя>.json          снимки состояния игры (мир + город): на них стоят кейсы will и seeding
  runs/<прогон>/             результат прогона
    report.md                итог, таблица агентов, разговор, что вышло в игре
    agents/<агент>.md        каждый вызов агента: полный промпт, сообщения, ответ, токены, время
    calls.json               все вызовы целиком (для анализа и сравнений)
    cassette.json            ответы моделей: прогон можно повторить бесплатно
    state.json               состояние после этапа
    run.json                 модели, хеши промптов, итоги, предупреждения потока
  compare/<A>__<B>.md        сравнение двух прогонов
```

Агенты связаны через состояние, а не напрямую: вход каждого агента собирает сам поток
из снимка — тем же кодом, что и в игре. Хороший результат одного этапа сохраняется
снимком, и следующие этапы встают на него.

## Команды

```
npm run bench -- list
npm run bench -- run genesis cloud-fishers
npm run bench -- save-state <прогон> fishers-day0 --note "город рыбаков после генезиса"
npm run bench -- run will build-lighthouse
npm run bench -- run seeding lantern-template
npm run bench -- compare <прогон A> <прогон B>
```

Флаги `run`:

- `--replay <прогон>` — ответы берутся с кассеты того прогона. Изменился промпт агента —
  у него промах кассеты, и он идёт в настоящую модель; остальные агенты отвечают как раньше.
- `--live агент,агент` — эти агенты всегда идут вживую, даже если ответ на кассете есть.
  Вместе с `--replay` это «перебросить кубик» одному агенту, оставив остальных как были.
- `--model агент=провайдер:модель` — подменить модель агенту (A/B по моделям).
- `--label метка` — метка в имени прогона, например `before` / `after`.
- `--seed N` — сид рандома (по умолчанию из кейса или 1). Тот же сид — те же id и выборки.
- `--state имя` — подменить снимок кейса.

## Как тюнить

1. Прогнать этап на кейсе — получить отчёт.
2. Разобрать отчёт (можно вместе с Claude: «посмотри прогон … по city-brief»).
3. Поправить промпт или схему агента.
4. Повторить с `--replay <прошлый прогон> --label after`: агенты, которых правка не задела,
   ответят с кассеты бесплатно, вживую пойдёт только изменённый и те, чей вход поменялся.
5. `compare` двух прогонов — ответы агентов бок о бок.
6. Понравился результат этапа — `save-state`, и следующий этап стоит уже на нём.

## Ключи и деньги

Живые прогоны ходят в настоящие модели (`config/agents.yaml`). Ключи — `OPENAI_API_KEY`
и `ANTHROPIC_API_KEY` в окружении или в `.env` в корне (он не коммитится). Без ключей
работает только повтор с кассеты.

Claude запускает живые прогоны только по просьбе Ника.
